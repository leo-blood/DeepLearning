## Slide 1：背景与动机

### 神经 IR 的两大范式

```
单向量范式（DPR, ANCE）          多向量/后期交互（ColBERT v1）
    
 Query → LM → [    q    ]           Query → LM → [q₁][q₂]...[qₙ]
                    ↓ 点积                              ↓ MaxSim ∑
 Doc   → LM → [    d    ]           Doc   → LM → [d₁][d₂]...[dₘ]

 空间：小（1 向量/doc）             空间：大（M 向量/doc）
 效果：中等                         效果：更好
```

### ColBERT v1 的两个瓶颈

| 问题 | 量化 |
|------|------|
| 存储空间巨大 | MS MARCO: ~**154GB**（单向量仅需 ~26GB） |
| 监督质量有限 | BM25 随机负例，训练信号弱 |

**ColBERTv2 的目标**：两个问题同时解决

## Slide 3：后期交互回顾

### MaxSim 公式

$$S_{q,d} = \sum_{i=1}^{N} \max_{j=1}^{M} Q_i \cdot D_j^T$$

- $Q$：查询的 $N \times \dim$ 矩阵（每行一个 token 向量）
- $D$：段落的 $M \times \dim$ 矩阵

### 直觉

每个查询 token 在段落中"软搜索"最匹配的 token，然后汇总全部匹配分数

```
查询：  [Who] [is]  [CEO]  [of]  [Apple]
         ↓     ↓     ↓      ↓      ↓
       max   max   max    max    max
         ↓     ↓     ↓      ↓      ↓
段落：[Tim] [Cook] [is] [the] [chief] [executive] [officer] [of] [Apple]

CEO → chief executive officer（语义对齐）✅
```

## Slide 4：去噪监督（核心贡献 1）

### 原始监督方案的问题

```
标准三元组 (q, d⁺, d⁻)：

d⁺：人工标注相关段落（稀疏，可能有遗漏）
d⁻：BM25 随机采样（往往与查询差异大，太容易）

→ 负例太简单，无法训练出细粒度区分能力
→ 假负例：未标注但实际相关的段落被当作负例
```

### ColBERTv2 的去噪监督流程

```
步骤 1：用初始 ColBERT 检索 top-k 候选段落
           ↓ （这些候选语义相近，是真正的"难例"）
           
步骤 2：Cross-Encoder 打分
           MiniLM (22M参数，蒸馏版) 对每个候选段落打分
           ↓ （去噪：识别假负例，给出软标签）
           
步骤 3：构建 w-way 元组
           (q, p_highly_ranked_1, ..., p_low_ranked_w)
           每个段落有 Cross-Encoder 给出的概率分数
           ↓
           
步骤 4：KL 散度蒸馏训练
           min KL( ColBERTv2分布 || Cross-Encoder分布 )
```

### 为什么有效？

| 方面 | 效果 |
|------|------|
| 困难负例 | ColBERT 检索的 top-k 语义相近，更难区分 |
| 去噪正例 | Cross-Encoder 能识别未标注的真实相关段落 |
| 软标签蒸馏 | 保留段落间相对相关性，比硬标签信息量更丰富 |

## Slide 5：残差压缩（核心贡献 2）

### 问题：多向量表示存储巨大

```
ColBERT v1 存储：
  MS MARCO: 8.8M 段落 × 平均 ~55 token × 128维 × 4字节
  = 约 154 GB
```

### 残差压缩原理

**关键洞察**：BERT token 向量存在空间聚类特性

```
所有 token 向量
    ↓ k-means 聚类
  k 个聚类中心 C = {c₁, c₂, ..., cₖ}

对每个 token 向量 v：
  1. 找最近中心：centroid_id = argmin_i ||v - cᵢ||
  2. 计算残差：r = v - c_{centroid_id}
  3. 量化残差：每维用 b=2 bits 表示
  
存储：(centroid_id, 量化残差)   ← 比原向量小 6-10 倍！
```

### 压缩效果可视化

```
原始向量（128维 float32）：
[0.312, -0.187, 0.045, ..., 0.293]  ← 512 字节

聚类中心（已知，共享）：
c₁₄₂ = [0.300, -0.190, 0.050, ..., 0.290]

残差（小！）：
r = [0.012, 0.003, -0.005, ..., 0.003]  ← 量化后只需 ~32-64 字节

压缩后存储：(142, 量化残差)  ← 原来的 1/8 ！
```

## Slide 6：三阶段索引流程

### 阶段 1：中心选取

```
全集合段落 → 采样（∝ √集合大小）→ BERT 编码
     ↓
  k-means 聚类（k ∝ √总向量数）
     ↓
  聚类中心集合 C（永久存储）
```

### 阶段 2：段落编码

```
每批次段落 → BERT → token 向量
     ↓
  残差压缩：为每个向量找最近中心 + 量化残差
     ↓
  (centroid_id, 量化残差) → 写入磁盘
```

### 阶段 3：索引反转

```
构建倒排结构：
  中心 c₁  →  [向量 v₃, v₁₈, v₄₂₁, ...]（属于段落 p₂, p₇, ...）
  中心 c₂  →  [向量 v₅, v₂₃, ...]
  ...

→ 支持：给定查询 token 向量 → 快速找到候选段落
```

## Slide 7：两阶段检索

### 在线检索流程

```
查询 q
  ↓ 编码
Q = [q₁, q₂, ..., qₙ]（N 个向量）

━━━ 阶段 1：近似候选检索 ━━━
  对每个 qᵢ，在 C 中找最近中心
  → 取该中心对应的所有向量（候选文档 token）
  → 映射回文档 ID → 候选文档集合 K

━━━ 阶段 2：精确 MaxSim 重排 ━━━
  对 K 中每个文档，精确计算 MaxSim 分数
  → 残差解压缩 + 精确余弦相似度
  → 返回 top-k 最终结果
```

### 效率来源

- 阶段 1：只需在压缩域做近似搜索（快）
- 阶段 2：只对少量候选做精确计算（可控）

| 方法 | MRR@10 | 索引空间（GB） |

| BM25 | 18.4 | - |

| ANCE | 33.0 | ~26 |
| ColBERT v1 | 36.0 | **~154** |
| **ColBERTv2** | **39.7** | **~25** |

```
效果：ColBERTv2 vs ColBERT v1：+3.7 MRR@10（+10% 相对提升）✅
空间：154GB → 25GB：压缩 6.2 倍                               ✅
空间：与单向量 DPR 相当（25GB ≈ 26GB）                         ✅
```

## Slide 10：压缩质量分析

### 不同量化精度 b 的影响（MS MARCO Dev）

| 量化位数 b | 存储（GB） | MRR@10 | 相对效果损失 |
|-----------|:--------:|:------:|:----------:|
| 无压缩（float32）| ~154 | 39.7 | 0% |
| b=4 bits | ~40 | ≈39.6 | <0.3% |
| **b=2 bits** | **~25** | **≈39.7** | **≈0%** |
| b=1 bit | ~15 | 39.0 | 1.8% |

**结论**：b=2 是最佳权衡点，压缩 6 倍几乎**无损**

### 为什么近乎无损？

```
ColBERT token 向量的空间分布：
    ·  ·  ·
  ·  ×  ·          × = 聚类中心
·  ·  · · ·        · = 实际向量（聚集在中心附近）
  ·  ×  ·
    ·  ·  ·

残差 = 向量到中心的距离 → 本身就很小
量化误差占整体距离的比例 → 微不足道
```

## Slide 12：总结与关键外卖

### ColBERTv2 三大贡献

```
1. 去噪监督
   Cross-Encoder 打软分 + 困难负例
   → 提升训练质量，效果显著提升

2. 残差压缩
   k-means 中心 + b=2 bits 量化残差
   → 6-10× 压缩，近乎无损

3. LoTTE 基准
   更贴近真实需求的域外评估资源
```

### 核心设计哲学

> 不要抛弃多向量表示的效果优势，而是通过**聪明的压缩**保留它。

### 对后续工作的影响

- RAGatouille：将 ColBERTv2 打包为易用的 RAG 检索器
- DSP（Demonstrate-Search-Predict）：ColBERTv2 作为核心检索组件
- 代码搜索、多跳推理、医学 IR 等多个领域的应用
