## Slide 1：问题设定

### 信息检索的两阶段范式

```
用户查询 q
    │
    ▼
┌─────────────────────────────┐
│  第一阶段：召回（Retrieval）  │
│  BM25 / 倒排索引              │
│  → top-1000 候选段落          │
└─────────────────────────────┘
    │
    ▼
┌─────────────────────────────┐
│  第二阶段：重排序（Re-ranking）│
│  精排模型（本文）              │
│  → top-k 最终结果             │
└─────────────────────────────┘
```

**核心问题**：如何设计高质量的重排序模型？

## Slide 2：BERT 简介回顾

### BERT 的核心机制

| 组件 | 说明 |
|------|------|
| 输入格式 | `[CLS] 句子A [SEP] 句子B [SEP]` |
| 编码器 | 双向 Transformer（Large: 24层, 16头, 1024维） |
| 预训练任务 | 掩码语言模型（MLM）+ 下一句预测（NSP） |
| `[CLS]` 向量 | 聚合全序列信息，用于分类任务 |

### BERT 为什么适合重排序？

- 双向注意力：查询 token 可直接关注段落 token（反之亦然）
- 大规模预训练知识：无需大量标注即可泛化

## Slide 3：Cross-Encoder 架构

### 模型输入与输出

```
查询："苹果公司的CEO是谁？"
段落："蒂姆·库克是苹果公司的首席执行官..."

输入：[CLS] 查询(≤64 token) [SEP] 段落(≤512-64 token) [SEP]
                        ↓
                   BERT-Large
                        ↓
                  [CLS] 向量 (1024维)
                        ↓
               Linear Layer (1024→1)
                        ↓
                相关性得分 s ∈ (0,1)
```

### 为何称为 "Cross-Encoder"？

查询和段落**同时输入**同一编码器，通过注意力机制**充分交互** → 效果强，但无法预计算

---

## Slide 4：训练目标

### 二分类损失

$$\mathcal{L} = -\sum_{j \in J_{pos}} \log(s_j) - \sum_{j \in J_{neg}} \log(1 - s_j)$$

### 训练数据构建

```
MS MARCO 训练集
├── 正例 d⁺：人工标注相关段落
└── 负例 d⁻：BM25 top-1000 中未标注的段落

三元组：(查询 q, 正例 d⁺, 负例 d⁻)
```

### 训练配置

| 参数 | 值 |
|------|---|
| 硬件 | TPU v3-8 |
| Batch Size | 128 |
| 最大序列长度 | 512 |
| 训练迭代 | 100k（约30小时） |
| 使用数据量 | ~1280万对（占完整数据集 **2%**）|

## Slide 5：实验结果

### MS MARCO 与 TREC-CAR 结果对比

| 方法 | MS MARCO Dev MRR@10 | TREC-CAR MAP |
|------|:-------------------:|:------------:|
| BM25（无调参） | 16.7 | 12.3 |
| KNRM | 21.8 | - |
| Conv-KNRM | 29.0 | - |
| IRNet（前SOTA） | 27.8 | - |
| **BERT Base（本文）** | **34.7** | **31.0** |
| **BERT Large（本文）** | **36.5** | **33.5** |

### 提升幅度

BERT Large vs. IRNet（前SOTA）：**MRR@10 +27%（相对提升）**

## Slide 7：Cross-Encoder 的瓶颈

### 优点 ✅
- 查询-段落**充分交互**，效果最强
- 实现简单，微调直接

### 缺点 ❌
- **无法预计算**：必须对每个（查询, 段落）对实时推理
- **延迟高**：1000 候选 × BERT-Large 前向传播 = 数秒
- **吞吐量低**：工业部署受限

### 延迟问题的数量级

| 方法 | 延迟（近似） |
|------|------------|
| BM25 | < 10ms |
| Cross-Encoder（CPU） | ~10分钟/query |
| Cross-Encoder（GPU） | ~30,000ms/query |

> 这一瓶颈直接催生了 ColBERT 的研究动机

## Slide 8：总结

### 本文贡献

1. **验证可行性**：BERT Cross-Encoder 可大幅提升段落重排序效果
2. **揭示数据效率**：少量标注数据 + 预训练 = 强效
3. **树立基线**：成为后续工作的重要基准

### 核心思想

```
预训练语言模型（BERT）
    + 大规模标注数据（MS MARCO）
    + 微调（Fine-tuning）
    = 强大的段落重排序器
```

### 历史意义

这篇论文是 **Dense Retrieval 时代的开端**，直接推动了：
- ColBERT（后期交互）
- DPR（双编码器）
- Sentence-BERT（句子嵌入）

等高效检索方法的提出。

## 附：关键术语

| 术语 | 含义 |
|------|------|
| Cross-Encoder | 查询和文档拼接后同时编码的模型 |
| Re-ranking | 对初始检索结果重新排序 |
| MRR@10 | Mean Reciprocal Rank，衡量第一个相关结果在前10中的位置 |
| BM25 | 基于词频的经典检索算法 |
| Fine-tuning | 在预训练基础上针对下游任务微调 |
