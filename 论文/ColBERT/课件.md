## Slide 1：动机——效率与效果的矛盾

### Cross-Encoder 的困境

```
BERT Cross-Encoder 排序流程：

查询 q  ─┐
         ├─→ [CLS] q [SEP] d₁ [SEP] → BERT → s₁  ┐
段落 d₁  ─┘                                         │
                                                    │ 1000次
查询 q  ─┐                                          │ 独立推理
         ├─→ [CLS] q [SEP] d₂ [SEP] → BERT → s₂  ┤
段落 d₂  ─┘                                         │
         ...                                        │
查询 q  ─┐                                          │
         ├─→ [CLS] q [SEP] d₁₀₀₀ [SEP] → BERT → s₁₀₀₀ ┘
段落 d₁₀₀₀─┘

延迟：~30,000ms（GPU），无法实用！
```

**核心问题**：如何在保持 BERT 表达能力的同时，大幅提升检索效率？

## Slide 2：四种检索范式对比

```
(a) 表示相似度（DSSM）          (b) 查询-文档交互（KNRM）
    Query ──→ [向量 q]               Query ─┐
                       ↘ 点积           Doc  ─┴→ 交互矩阵 → CNN → 分数

    ✅快  ❌效果差                   ✅中速  △效果中等

(c) 全对全交互（BERT）           (d) 后期交互（ColBERT ← 本文）
    [CLS] Query [SEP] Doc            Query ──→ BERT → [q₁,q₂,...,qₙ]
         ↓                                                    ↓
       BERT                                              MaxSim ∑
         ↓                           Doc ────→ BERT → [d₁,d₂,...,dₘ]
        分数
    ❌最慢  ✅效果最好              ✅快  ✅效果好（本文目标）
```

## Slide 3：ColBERT 核心思想

### 后期交互（Late Interaction）

**关键洞察**：将编码和交互解耦

```
        离线预计算（慢，一次性）
        ┌──────────────────────────────┐
        │  Doc → BERT → [d₁,d₂,...,dₘ] │  存入索引
        └──────────────────────────────┘

        在线查询（快，实时）
        ┌──────────────────────────────┐
        │  Query → BERT → [q₁,q₂,...,qₙ]│  仅计算查询
        └──────────────────────────────┘
                    ↓
              MaxSim 交互（廉价）
                    ↓
                相关性分数
```

文档向量**预计算并存储**，查询时只需做轻量 MaxSim 操作！

## Slide 4：模型架构详解

### 查询编码器 f_Q

```
输入：[Q] 苹果 公司 CEO 是 谁 [MASK] [MASK] [MASK]
              ↓（补齐至固定长度，[MASK] 用于"查询增强"）
          BERT Encoder
              ↓
       每个 token 的上下文嵌入（768维）
              ↓
          线性投影（→ 128维）
              ↓
           L2 归一化
              ↓
    Eq = {q₁, q₂, q₃, q₄, q₅, q₆, q₇, q₈}（N个向量）
```

### 文档编码器 f_D

```
输入：[D] 蒂姆 库克 是 苹果 公司 的 首席 执行官
              ↓（标点符号的嵌入被过滤）
          BERT Encoder
              ↓
       每个 token 的上下文嵌入（768维）
              ↓
          线性投影（→ 128维）+ L2 归一化
              ↓
    Ed = {d₁, d₂, d₃, d₄, d₅, d₆, d₇, d₈}（M个向量）
```

## Slide 5：MaxSim 后期交互

### 相关性计算公式

$$S_{q,d} = \sum_{i=1}^{|E_q|} \max_{j=1}^{|E_d|} \mathbf{E}_{q_i} \cdot \mathbf{E}_{d_j}^T$$

### 直觉图示

```
查询 token:  [苹果]  [公司]  [CEO]  [是]  [谁]
                ↓       ↓      ↓     ↓     ↓
              max     max    max   max   max    ← 在文档向量中找最相近的
                ↓       ↓      ↓     ↓     ↓
文档 token: [蒂姆]  [库克]  [苹果] [公司] [CEO] [首席] [执行官]

每个查询 token 找到最匹配的文档 token：
  苹果 → 苹果（完全匹配）
  公司 → 公司（完全匹配）
  CEO  → 首席执行官（语义匹配！）
  谁   → 蒂姆库克（语义匹配）

总分 = 各 token 最大相似度之和
```

## Slide 6：查询增强技巧

### 为什么用 [MASK] 填充查询？

```
原始查询（5个 token）：  [Q] 苹果 公司 CEO
填充后（32个 token）：   [Q] 苹果 公司 CEO [M] [M] [M] ... [M]

BERT 中 [MASK] 会与其他 token 进行注意力交互
→ [MASK] 的输出向量携带了查询上下文信息
→ 相当于"虚拟扩展"了查询的表达空间
```

**消融实验**：去掉 [MASK] 填充，MRR@10 下降约 **0.3 点**

### [Q] 和 [D] 标记

- `[Q]`：标识这是查询，帮助模型区分输入类型
- `[D]`：标识这是文档

## Slide 7：离线索引与在线检索

### 两种检索模式

#### 模式 1：重排序（Re-ranking）

```
BM25 → top-1000 候选段落
             ↓
   ColBERT MaxSim 精排
             ↓
        最终 top-k
```

#### 模式 2：端到端全集合检索

```
查询向量 Eq = {q₁, q₂, ..., qₙ}
         ↓
对每个 qᵢ，用 FAISS 检索最近邻文档 token 向量（top-k'）
         ↓
将命中 token 映射回文档 → 获得候选文档集合 K
         ↓
对 K 个文档做精细 MaxSim 重排
         ↓
返回最终结果
```

**FAISS IVFPQ 索引**：
- 将向量空间分成 P 个单元（k-means）
- 每个向量分 s 个子向量，每个子向量用 1 字节编码
- 查询时只搜索最近的 p 个单元（剪枝）

## Slide 8：实验结果

### MS MARCO 重排序（Dev 集）

| 方法 | MRR@10 | 延迟 |
|------|:------:|:----:|
| BM25 | 18.4 | ~10ms |
| KNRM | 21.8 | 低 |
| Conv-KNRM | 29.0 | 低 |
| Duet | 24.3 | 低 |
| BERT Cross-Encoder | 36.0 | **~30,000ms** |
| **ColBERT（重排序）** | **36.0** | **~45ms** |

### 关键数据


## Slide 10：ColBERT 的局限与后续工作

### 遗留问题

| 问题 | 量化 | ColBERTv2 解决方案 |
|------|------|------------------|
| 存储空间大 | MS MARCO 需 ~154GB | 残差压缩 → ~25GB |

## Slide 11：总结

### ColBERT 三大创新

```
1. 后期交互范式（Late Interaction）
   → 平衡效率与效果的新思路

2. MaxSim 操作
   → 廉价、可剪枝的 token 级交互

3. 离线预计算文档向量
   → 查询时仅需轻量计算
```

### 一句话总结

> ColBERT 通过**延迟交互**而非**消除交互**，在不牺牲效果的前提下将 BERT 检索速度提升了 2 个数量级。

## 附：核心公式速查

| 公式 | 含义 |
|------|------|
| $E_q = f_Q(q)$ | 查询编码为 N 个向量 |
| $E_d = f_D(d)$ | 文档编码为 M 个向量 |
| $S_{q,d} = \sum_i \max_j E_{q_i} \cdot E_{d_j}^T$ | MaxSim 相关性分数 |
| 损失：pairwise softmax 交叉熵 | 用 $(q, d^+, d^-)$ 三元组训练 |
